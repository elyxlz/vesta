# Ocado (CLI: ocado)

Reverse-engineered from ocado.com's own web API. Every call is a `fetch()` run inside the signed-in
`browser` session `ocado` (Chromium), so cookies, the AWS WAF token and the CSRF token are always
the browser's own: no cookie export, no WAF fights. Each API call is one `browser exec` (a few
seconds; a command can make several). Whatever you change is the user's real trolley/lists, visible on the web immediately.

Product refs accept a productId (uuid), a retailerProductId/SKU (the number at the end of a product
URL, e.g. `78922011`), or a full product URL. `ocado search` prints both.

```bash
ocado status                         # signed in?
ocado login                          # password from ~/.ocado/cred.json, emailed code pulled from the inbox

ocado search "semi skimmed milk" --limit 5
ocado product 78922011

ocado trolley                        # what's in it now, total, minimum, checkout blockers
ocado add 78922011 --qty 2
ocado remove 78922011 [--qty 1]      # all of that line by default
ocado set 78922011 3                 # exact quantity (0 removes)
ocado --json trolley > snap.json     # snapshot ...
ocado restore snap.json [--yes]      # ... and put it back exactly (--yes when it removes lines)
ocado empty --yes

ocado orders                         # upcoming (with editable-until) + past
ocado order <orderId>                # lines, subs, totals
ocado order-again <orderId>          # Ocado's own "Order again": adds the order to the trolley
ocado order-again <orderId> --empty-first --yes   # replace the trolley with it
ocado edit <orderId> [--cancel]      # open/discard amendment of a pending order (UNTESTED)

ocado favs [--limit 50]
ocado fav add|remove <product>

ocado regulars
ocado regular add <product> [--qty 1] [--frequency WEEKLY|FORTNIGHTLY|MONTHLY]   # add or update
ocado regular remove <product>

ocado lists
ocado list show "<name or id>"
ocado list create "<name>" [products...]
ocado list add|remove "<list>" <product> [more...]
ocado list rename "<list>" --name "<new>"
ocado list delete "<list>" --yes
ocado list to-trolley "<list>"

ocado slots [--days 7] [--all]       # bookable delivery slots, price, GREEN badge
ocado reserve <slotId>               # UNTESTED: holds a slot
```

`--json` (anywhere on the line) gives machine-readable output; `--pretty` indents it.

## Rules

- **The trolley is the handoff.** Build it, tell the user the total and what's in it, and let them
  check it on the web. Before any change to a trolley the user already built, snapshot it
  (`ocado --json trolley > <snapshot dir>/<date>-<why>.json`) so `restore` can undo it.
- **Placing or amending an order is an outward action with money**: only on the user's explicit go
  for that specific order. Checkout is intentionally not in this CLI; the site's chain is
  checkout-start, checkout-summary, T&C acknowledge, pspweb checkout/complete. Build and test it
  with the user watching, never blind.
- Destructive commands (`empty`, `list delete`, `order-again --empty-first`, and a `restore` that would reduce or remove lines) refuse without `--yes`; `restore` without it prints the plan first.
- Minimum order is £40; `ocado trolley` prints the blockers (`NOT_REACHED_THRESHOLD`, `MISSING_SLOT`).
- Report what Ocado's response says, not what you asked for: `add` prints `limited`/`unavailable`.
- Include each product's link (printed on every row) when sharing products with the user.
- Label options a, b, c (never 1, 2, 3): the user answers with numbers as quantities ("2b" = 2 of option b).

## Sign-in

`ocado login` types the saved credential into sso.ocado.com (Salesforce login, fields live in shadow
DOM), then reads the one-time code Ocado emails to the account address via the `microsoft` CLI and
submits it. The code is never printed, and the email body is read from a temp file deleted at once. The new-mail notification preview can still carry the code: scrub it from history in the nightly dream. If the login page changes and it fails, fall back to
`browser handover start --session ocado --url https://www.ocado.com/login` and let the user sign in.
A command answering `not logged in` means the session expired: run `ocado login`.

## Internals

- The API map can be regenerated by capturing the site's own network calls in the browser session.
  GraphQL introspection is off; queries must not declare unused variables (the server rejects them).
- Results travel through a private temp file, not stdout (browser stdout is capped ~260KB).
- Region defaults to England's id; delivery destination defaults from the trolley; override in
  `~/.ocado/config.json` (`regionId`, `deliveryDestinationId`).
- Regular frequencies accepted by the API: `WEEKLY`, `FORTNIGHTLY`, `MONTHLY` (the site UI shows Weekly).
